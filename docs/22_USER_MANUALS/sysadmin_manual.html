1. SysAdmin Superuser Privileges & Architecture

The SysAdmin role represents the highest level of administrative authorization within the PrathamOne EduOS enterprise architecture. SysAdmin accounts possess unrestricted visibility across all application modules, as well as exclusive capabilities:

  • Universal Records Editor: Surgical in-place editing of master data records across 8 core database models with strict allowlist enforcement.
  • Posted Payments Security Gate: Exclusive authority to unlock and correct posted financial ledger transactions.
  • Immutable Security Audit Logs: Complete forensic surveillance of all administrative updates, document generation, and authentication events.
  • Multi-Branch Tenant Isolation Management: Supervision of institutional settings, branch hierarchies, and data isolation boundaries.
SysAdmin Operations Center with Server Diagnostics & Security Logs.

2. Universal Records Editor & Field Allowlists

Located in the SysAdmin Center (/sysadmin), the Universal Records Editor allows authorized superusers to correct operational anomalies (e.g. spelling errors, wrong exit dates, misallocated contact numbers) directly through the authenticated API without requiring terminal database access.

Mandatory Reason Requirement

Every universal edit requires an explicit administrative reason. Missing or whitespace reasons are rejected by the backend with HTTP 400 Bad Request.

3. Posted Payment Security Gate & Receipt Integrity

Financial ledger security requires that posted transactions cannot be altered by front-desk or accounting personnel. When a legitimate correction is required (e.g. cheque clearance dishonor, wrong fee head mapping), SysAdmin operates the Posted Payment Security Gate:

Posted Payment Security Gate Modal Dialog.
  1. Security Gate Verification
    SysAdmin enters the payment record ID and authenticates the unlock action.
  2. Mandatory Edit Reason
    SysAdmin enters a comprehensive justification for the transaction correction.
  3. Receipt Supersession & Audit Recording
    The backend updates the payment, marks the original receipt as superseded (is_superseded = True), and issues a versioned revision. Receipt sequence numbers are never deleted or renumbered.

4. Security Audit Logs & Telemetry

All sensitive operations across PrathamOne EduOS generate structured audit logs stored in the PostgreSQL audit_logs table. These can be reviewed in real time via the SysAdmin Center (/sysadmin → Security Audit Logs):

  • Actor & Identity: User ID, Username, and Role of the actor.
  • Resource Type & ID: Target entity (e.g. student:129, payment:45).
  • Before / After Diff: Complete JSON snapshot of modified fields (old_data vs new_data).
  • Origin Network: Client IP address and browser User-Agent header.
