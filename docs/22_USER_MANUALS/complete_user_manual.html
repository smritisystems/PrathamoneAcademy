1. Welcome & Product Architecture Overview

1.1 Executive Summary & Mission

PrathamOne EduOS (part of the PrathamOne Coaching Institutes Enterprise Suite) is an enterprise-grade ERP and academic operations platform engineered specifically for coaching institutes, competitive exam academies, tutoring centers, and multi-branch educational networks. Engineered by Jawahar R Mallah and the team at AITDL (AI Technology & Development Lab), PrathamOne EduOS consolidates fragmented institute workflows into a unified, secure, high-performance web platform.

The platform delivers complete lifecycle management across five core institutional pillars:

  • Academic Operations: Hierarchical curriculum structuring spanning Educational Boards, Standards, Subjects, Divisions, Batches, and Weekly Timetables.
  • Student Lifecycle: Comprehensive onboarding, automated student registration number generation (PA-2024-XXXXXX), KYC compliance document archiving, exit/withdrawal tracking, and one-click reactivation.
  • Financial Governance: Flexible fee plan configuration, installment scheduling, scholarship concessions, automated payment ledger, tamper-proof sequential receipting, posted-payment security gates, and linked refund processing.
  • Faculty & Attendance: Real-time roster tracking, mobile-friendly bulk attendance marking, faculty assignment, and automated defaulter alerts.
  • Compliance & Enterprise Security: Granular 8-tier Role-Based Access Control (RBAC), Digital Personal Data Protection (DPDP) compliance audit logs, Universal Data Editing with strict field allowlists, and immutable system event journaling.

3. Getting Started & Authentication

3.1 Logging into PrathamOne EduOS

To access the system, navigate to the application URL in any modern web browser (Google Chrome, Mozilla Firefox, Microsoft Edge, or Safari):

http://localhost:80/login (or your institute's custom production domain).
Figure 3.1: PrathamOne EduOS Secure Sign-In Portal.
  • Enter Your Credentials
    Enter your designated Username or Registered Email address in the Username or Email input field.
  • Enter Your Password
    Type your password into the Password field. Passwords are case-sensitive and must satisfy enterprise security policies.
  • Submit & Authenticate
    Click the blue Sign In button. Upon successful verification, an encrypted JWT authentication token is issued, and you are automatically redirected to your role's default dashboard workspace.
Default First-Time Credentials

Initial system deployment includes a pre-seeded Sysadmin superuser account (sysadmin). Upon first login, navigate immediately to User Profile or System Settings to rotate your password to a strong, confidential passphrase.

4.2 Academic Structure & Batch Management

Route: /academic  |  Access: SysAdmin, Superadmin, Admin, Principal

Purpose: The Academic Structure workspace configures the foundational organizational hierarchy of your academy. All courses, batches, timetables, and fee plans link directly to this structure.

Figure 4.2: Academic Hierarchy Manager configuring Educational Boards, Standards, and Batches.

Step-by-Step Task: Creating an Educational Board

  1. Navigate to Academic Structure from the sidebar.
  2. Click on the Boards tab.
  3. Click the blue Add Board button in the top right.
  4. Fill in the required fields:
    • Board Name (Required): e.g., Central Board of Secondary Education.
    • Board Code (Required, Unique): e.g., CBSE.
    • Description (Optional): Brief notes regarding curriculum coverage.
  5. Click Save Board. The board appears instantly in the active roster.

Step-by-Step Task: Creating a Standard / Grade

  1. Click on the Standards tab.
  2. Click Add Standard.
  3. Select the parent Board from the dropdown.
  4. Enter Standard Name (e.g., 10th Standard) and Level / Code (e.g., STD-10).
  5. Click Save Standard.

Step-by-Step Task: Creating a Division / Batch

  1. Click on the Batches / Divisions tab.
  2. Click Add Batch.
  3. Select the Standard (e.g., 10th Standard).
  4. Enter Batch Name (e.g., Morning Champions Batch A) and Batch Code (10-A-MORN).
  5. Set Maximum Capacity (e.g., 45) and Room Number (e.g., Classroom 204).
  6. Assign the Class Teacher / Mentor from the faculty list.
  7. Click Save Batch.

4.4 Student Admission & Lifecycle Management

Routes: /students, /students/add, /students/{id}

Purpose: Complete student relationship management from prospective inquiry to formal admission, active enrollment, academic tracking, KYC compliance verification, withdrawal, and reactivation.

Figure 4.5: Filterable Students Directory with multi-criteria search and CSV export.

Step-by-Step Task: Admitting a New Student

  1. Click Students → Add Student (or navigate to /students/add).
  2. Complete the 4-step wizard:
    • Step 1: Personal Profile: First Name, Middle Name, Last Name, Date of Birth, Gender, Blood Group, Aadhaar Number, Category/Caste.
    • Step 2: Contact Information: Student Mobile, WhatsApp Number, Email, Residential Address, City, State, Pincode.
    • Step 3: Academic Allocation: Target Board, Standard, Division/Batch, Roll Number, Enrollment Date.
    • Step 4: Parent / Guardian Details: Father's Name, Mother's Name, Guardian Phone, Guardian Email, Occupation, Annual Income.
  3. Click Submit Admission. The system assigns a unique permanent Registration Number (e.g., PA-2024-000001) and opens the comprehensive Student Detail Profile.
Figure 4.6: Multi-Step Student Admission Wizard.
Figure 4.7: Student Detail Profile Workspace showing tabs for Academics, Fees, Attendance, and KYC.

Student Lifecycle Actions:

  • Edit Profile Modal: Click the Edit Profile button to update address, contact numbers, or guardian details without altering registration or ledger history.
  • Student Withdrawal / Exit: Click Exit Student. A modal prompts for mandatory Exit Date, Exit Reason (Transfer, Financial, Health, Course Completed, Other), and administrative exit notes. Once exited, the student's status changes to EXITED and seat capacity in the batch is freed.
  • Student Reactivation: If a withdrawn student re-enrolls, authorized administrators (Admin, Sysadmin) can click Reactivate Student, re-assign them to an active batch, and restore active status.
  • KYC Document Management: Upload digital scans of Aadhaar Card, Transfer Certificate, Previous Marks Sheet, and Birth Certificate. Toggle document verification status (VERIFIED / PENDING).

4.5.D Multi-Table Delete Protection & Workforce Safeguards

To prevent catastrophic data loss and audit corruption, PrathamOne EduOS enforces strict referential delete protection across 7 relational domains:

  • Hard Deletion Barrier: Attempting to permanently delete a user with existing payroll records, teaching sessions, batch assignments, attendance punches, leave records, payment vouchers, or student enrollments returns an explicit HTTP 400 Bad Request error blocking the operation.
  • Soft Deactivation Workflow: Instead of deletion, clicking Deactivate marks is_active = False and sets employment status to INACTIVE, immediately revoking login access while preserving all financial and academic historical records.

4.8 Payments Ledger & Posted Edit Security Gate

Route: /payments  |  Access: Accountant, Admin, Principal, SysAdmin

Purpose: Financial transaction ledger managing the collection, draft generation, verification, receipt generation, and posting of tuition fees.

Figure 4.13: Complete Payments Financial Ledger with status filtering and receipt reprint links.

Payment Status Lifecycle:

  • DRAFT: Initial payment entered by front-desk staff. Editable freely by accountants and staff. No permanent receipt number is locked.
  • SUBMITTED: Payment submitted for verification. Edits require an explicit administrative reason.
  • POSTED: Fully verified and posted to the general financial ledger. A permanent, sequential receipt number (e.g., REC-2026-000142) is generated and locked.
  • REFUNDED: Transaction has undergone a full or partial refund. Refund records are maintained as distinct negative ledger entries linked to the original payment via parent_payment_id.
Financial Control: Posted Payment Security Gate

Ordinary staff, teachers, and accountants CANNOT edit or delete a POSTED payment. In order to protect ledger integrity and comply with accounting audit standards, only a user with the explicit payments:edit_posted permission (Sysadmin) can unlock and edit a posted transaction.

Figure 4.14: Posted Payment Security Gate modal enforcing authorization and mandatory reason logging.

4.19 CodeX — Configurable Feature Activation & Numeric Coding Studio

Route: /codex  |  Access: Business Owner / Authorized SysAdmin Exclusive

Purpose: Optional, highly secure numeric obfuscation engine that masks sensitive business figures (salaries, prices, fees, profit margins) using custom owner-defined alphanumeric symbol mappings.

Mandatory System Default Policy: DISABLED (OFF)

In accordance with global governance directives, CodeX is DISABLED by default everywhere. Installing, updating, or initializing software will never auto-activate CodeX. It requires explicit, authorized activation by the Business Owner.

Figure 4.26A: CodeX Configuration Studio featuring master activation toggle and 16 granular feature controls.

Core Architectural Capabilities:

  • Bijective Reversible Mapping: Digits 0 through 9 map to unique custom symbols (e.g., 0→Q, 1→A, 2→Z, 3→M, 4→K, 5→P, 6→X, 7→B, 8→T, 9→R). An amount of ₹ 12,500 displays as AZPQQ, and decodes back to 12500.
  • Granular 16-Feature Control: Independently enable or disable CodeX across Student Fees, Teacher Payroll, Salary Slips, Invoices, Receipts, and Reports.
  • Scoped Visibility Overrides: Define access policies per Department, Role, or Individual User (e.g., Accountants see real figures while front desk sees coded values).
  • PIN Protection & QR Decoder: Decoding coded numbers requires administrative PIN verification. Mobile managers can scan QR codes to decode paper receipts.
Figure 4.26B: Interactive Digit Mapping Studio with live substitution preview.
Figure 4.26C: Verification Sandbox testing live bidirectional encoding and decoding before deployment.

5. End-to-End Business Workflows

5.1 Workflow 1: Student Onboarding from Admission to Batch Enrollment

  1. Inquiry & Registration
    Parent/Student arrives. Front desk opens /students/add and enters personal, contact, and academic details.
  2. Batch & Division Assignment
    Student is assigned to the appropriate Standard (e.g., 10th CBSE) and Batch (Morning Champions Batch A). Roll number is allocated.
  3. Fee Plan Commitment
    The standard fee plan is automatically mapped to the student profile, establishing the student's fee obligation and installment timeline.
  4. Identity Card & Admission Form Generation
    One-click generation of the Student ID Card and Admission Record from /forms.

5.2 Workflow 2: Financial Collection, Receipting, Correction & Refunds

  1. Payment Collection
    Accountant receives cash, cheque, or UPI payment via /payments → Record Payment.
  2. Sequential Receipt Issuance
    System generates permanent sequential receipt (REC-2026-XXXXXX) and posts to financial ledger.
  3. Posted Payment Correction (If Required)
    If a mistake occurred, Sysadmin accesses the Posted Payment Security Gate with an explicit reason. The original receipt is marked as superseded, and a new versioned receipt is issued. Historical numbers are never deleted.
  4. Processing a Refund
    If a student withdraws, an authorized accountant processes a linked refund via the Payments module. The refund references the original payment ID and updates the net balance.

7. Troubleshooting, Error Codes & Support

7.1 Common Runtime Errors & Resolving Taxonomy Codes

PrathamOne EduOS features a centralized, taxonomy-based error monitoring architecture. When an error occurs, a user-friendly modal is displayed along with a unique reference code (e.g., ERR-20261106-XXXX):

Taxonomy Category Typical Root Cause Recommended User Resolution
INTERNET_DISCONNECTED Local Wi-Fi or ethernet drop. Check router connection. The application PWA will operate in offline cache mode until connection is re-established.
SESSION_EXPIRED (HTTP 401) JWT token lifetime exceeded (8 hours). The system automatically redirects you to /login once. Re-enter your password to renew session.
PERMISSION_DENIED (HTTP 403) Current user role lacks permission for the requested action. Contact your institute Administrator or Sysadmin to assign appropriate permissions.
RESOURCE_NOT_FOUND (HTTP 404) Target student ID or record does not exist or was removed. Verify the record ID in the directory. Deleted records can be inspected in the Audit Log.
VALIDATION_FAILED (HTTP 400/422) Missing mandatory field (e.g., Edit Reason) or duplicate unique key. Review highlighted input fields in red. Ensure an administrative reason is provided for transaction modifications.

7.2 Frequently Asked Questions (FAQ)

Q: Can I edit a fee payment after the receipt has been printed?
A: Yes, but only with authorized Sysadmin credentials via the Posted Payment Security Gate. The system preserves the original receipt for audit compliance and marks it as superseded.

Q: How do I export my student roster to Excel?
A: Go to Students or Reports, set your desired filters, and click the green Export to Excel / CSV button at the top right of the table.

Q: What happens when a student withdraws? Does it delete their fee history?
A: No! Financial records and attendance history are permanently preserved. The student's status is simply marked as Exited, freeing up batch capacity.
